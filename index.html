What is Lex?

Understanding the lexical analyzer generator

🔍

Definition

Lex (Lexical Analyzer Generator) is a tool that generates a lexical analyzer (scanner/tokenizer) from regular expression rules. Commonly used with Yacc/Bison for building compilers and interpreters.

⚙

How It Works

Write rules in a .l file → Lex generates lex.yy.c → Compile with GCC → The executable reads input and matches tokens based on your patterns.

🎯

What it Does

Reads characters from input, groups them into tokens (numbers, identifiers, keywords), and performs C actions you define for each matched token.

Lex File Structure

The three sections of every .l file

Section 1
Definitions
Include C headers, define macros, name regular expressions
%{ ... %} and name regex
%%
Section 2
Rules
Pattern–action pairs. When a pattern matches, the action (C code) runs.
pattern { action; }
%%
Section 3
User Code
C functions copied directly to output. Usually contains main().
int main() { yylex(); }
lex template.l – Basic Lex Template 
%{
#include<stdio.h>
%}

%%
[0-9]+    { printf("INTEGER: %s\n", yytext); }
[a-z]+    { printf("WORD: %s\n", yytext); }
[ \t\n]+  ;
.         { printf("OTHER: %s\n", yytext); }
%%

int yywrap(){ return 1; }

int main()
{
    yylex();
    return 0;
}
yytext
Holds the matched token string
yyin
Input file pointer (default: stdin)
yyout
Output file pointer (default: stdout)
yylex()
Starts the scanning loop
yywrap()
Called at end of file; return 1 to stop

Token Scanner – Lex Program
Write a Lex program to scan an input stream from a file and identify different types of tokens: Integer constants, Floating-point constants, Scientific Notation, Alphanumeric, and Identifiers. Write results to an output file.

📖 Token Types & Patterns

1. Scientific Notation
[0-9]+.[0-9]+[eE][+-]?[0-9]+
Examples: 1.5e10, 2E-3, 5e+6
2. Float Constant
[0-9]+\.[0-9]+
Examples: 3.14, 0.5, 99.99
3. Integer Constant
[0-9]+
Examples: 42, 100, 0
4. Alphanumeric
[a-zA-Z]+[0-9]+
Examples: abc123, x1y2
5. Identifier
[a-zA-Z][a-zA-Z0-9_]*
Examples: myVar, hello
⚠
Rule Order Matters! Lex tries rules top-to-bottom. Scientific must come BEFORE Float, and Float BEFORE Integer — otherwise 1.5e10 might be wrongly classified as Float or Integer.

%}

}

}

[ \t\n]+ ;

. ;

int yywrap()
{
    return 1;
}

🧠 Code Explanation

1
%{ #include<stdio.h> %}
Section 1: The C header is included here so we can use printf inside rule actions.
2
[0-9]+.[0-9]+[eE][+-]?[0-9]+
Matches scientific notation like 1.5e10 or 2E-3. Must be the FIRST rule to avoid shorter patterns stealing the match.
3
[ \t\n]+ ;
Whitespace and newlines are consumed silently (the ; is an empty action — do nothing).
4
fp=fopen("FILE.txt","r"); yyin=fp; out=fopen("OUTPUT.txt","w");
yyin is set to the input file pointer so the scanner reads from FILE.txt. out is a custom FILE* used with fprintf(out,...) to write token results to OUTPUT.txt.
5
int yywrap(){ return 1; }
Called when end of input is reached. Returning 1 tells Lex to stop scanning. Required, or you get a linker error.
Q2
FIRST of Grammar – C Program
WAP in C to find the First of the given grammar:
S → ABC | ghi | jkl,  A → a | b | c,  B → b,  D → d

📖 Understanding FIRST Sets

📚

What is FIRST?

FIRST(X) is the set of terminals that can appear as the first symbol derived from X. Crucial for building parsing tables in compiler design.

📏

Rules for FIRST

  • If X is a terminal → FIRST(X) = {X}
  • If X → ε → add ε to FIRST(X)
  • If X → Y₁Y₂... → add FIRST(Y₁) − {ε}
  • If ε ∈ FIRST(Y₁), also add FIRST(Y₂)

🔢 Manual FIRST Calculation

S → ABC | ghi | jkl
A → a | b | c
B → b
D → d
FIRST(A)
A → a | b | c → all terminals directly
= { a, b, c }
FIRST(B)
B → b → terminal directly
= { b }
FIRST(D)
D → d → terminal directly
= { d }
FIRST(S)
S → ABC: FIRST(A)={a,b,c}, no ε → add {a,b,c}, stop
S → ghi: first symbol = 'g' (terminal) → add g
S → jkl: first symbol = 'j' (terminal) → add j
= { a, b, c, g, j }
